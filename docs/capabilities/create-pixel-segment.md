# Яндекс Аудитории: Создать сегмент на основе пикселя — MCP-инструмент (tool)

**MCP-инструмент (tool) для Яндекс Аудиторий:** Создаёт сегмент типа pixel — пользователи, которых пиксель (pixel_id из list_pixels) видел за последние period_length дней (1..90).

Техническое имя: `create_pixel_segment`

## Какую задачу решает

> Я хочу создать сегмент на основе пикселя.

Создаёт сегмент типа pixel — пользователи, которых пиксель (pixel_id из list_pixels) видел за последние period_length дней (1..90).

## Когда использовать

Используйте эту возможность, когда нужен результат «Создать сегмент на основе пикселя» без ручной работы в интерфейсе Яндекс Аудиторий. Операция выполняется только по вызову из AI-приложения.

## Что нужно передать

- `name` — **обязательно**. Название сегмента.
- `pixel_id` — **обязательно**. Идентификатор пикселя (id из list_pixels), на основе которого строится сегмент.
- `period_length` — **необязательно**. Период в сутках (1..90), за который пользователь был замечен пикселем.
- `times_quantity` — **необязательно**. Пороговое количество срабатываний пикселя (используется вместе с times_quantity_operation).
- `times_quantity_operation` — **необязательно**. Условие по частоте: lt (меньше), eq (равно), gt (больше) относительно times_quantity.
- `utm_source` — **необязательно**. Фильтр по метке utm_source.
- `utm_medium` — **необязательно**. Фильтр по метке utm_medium.
- `utm_campaign` — **необязательно**. Фильтр по метке utm_campaign.
- `utm_content` — **необязательно**. Фильтр по метке utm_content.
- `utm_term` — **необязательно**. Фильтр по метке utm_term.
- `device_matching_type` — **необязательно**. Режим сопоставления устройств (недокументирован для pixel-сегментов, экспериментально).

## Что вернёт

Ответ — {"segment": {...}}.

## Что изменится в Яндекс Аудиториях

Инструмент изменяет реальные данные Яндекс Аудиторий так, как описано выше. Автоматического отката сервер не обещает.

## Пример запроса

> Создать сегмент на основе пикселя в Яндекс Аудиториях. Если не хватает обязательных идентификаторов, сначала уточни их.

## Возможные ошибки и ограничения

Дополнительные условия объединяются по «И»: частота показов (times_quantity + times_quantity_operation: lt | eq | gt) и фильтры по UTM-меткам (utm_source, utm_medium, utm_campaign, utm_content, utm_term). device_matching_type присутствует в примере запроса API, но не описан в документации — считайте экспериментальным. Квота: 10/мин, 100/час, 500/сутки.

Доступ также зависит от прав токена, квот и ограничений исходного API.
