# Яндекс Аудитории: Сохранить загруженный сегмент — MCP-инструмент (tool)

**MCP-инструмент (tool) для Яндекс Аудиторий:** Сохраняет сегмент, созданный из файла (второй шаг после upload_segment_file / upload_segment_csv_file): задаёт имя, тип содержимого и параметры хеширования.

Техническое имя: `confirm_segment`

## Какую задачу решает

> Я хочу сохранить загруженный сегмент.

Сохраняет сегмент, созданный из файла (второй шаг после upload_segment_file / upload_segment_csv_file): задаёт имя, тип содержимого и параметры хеширования.

## Когда использовать

Используйте эту возможность, когда нужен результат «Сохранить загруженный сегмент» без ручной работы в интерфейсе Яндекс Аудиторий. Операция выполняется только по вызову из AI-приложения.

## Что нужно передать

- `segment_id` — **обязательно**. Идентификатор сегмента (id из list_segments или из ответа создания).
- `name` — **обязательно**. Название сегмента.
- `content_type` — **обязательно**. Тип содержимого файла: idfa_gaid | mac | crm.
- `hashed` — **необязательно**. Захешированы ли данные в файле.
- `hashing_alg` — **необязательно**. Алгоритм хеширования — только SHA256 (MD5 не поддерживается с 01.01.2025).
- `device_matching_type` — **необязательно**. Режим сопоставления устройств: CROSS_DEVICE (по умолчанию) | IN_DEVICE (только для idfa_gaid).
- `check_size` — **необязательно**. false — разрешить сохранение сегмента меньше 100 записей (по умолчанию true).

## Что вернёт

Ответ — {"segment": {...}}; обработка занимает время, статус смотрите через list_segments.

## Что изменится в Яндекс Аудиториях

Инструмент изменяет реальные данные Яндекс Аудиторий так, как описано выше. Автоматического отката сервер не обещает.

## Пример запроса

> Сохранить загруженный сегмент в Яндекс Аудиториях. Если не хватает обязательных идентификаторов, сначала уточни их.

## Возможные ошибки и ограничения

content_type: idfa_gaid (идентификаторы мобильных устройств), mac (MAC-адреса) или crm (CSV с CRM-данными). hashing_alg — только SHA256 (MD5 не поддерживается API с 01.01.2025). device_matching_type: CROSS_DEVICE (по умолчанию) или IN_DEVICE (только для idfa_gaid). check_size=false позволяет сохранить сегмент меньше 100 записей (его нельзя использовать в Директе, пока размер не превысит 100).

Доступ также зависит от прав токена, квот и ограничений исходного API.
